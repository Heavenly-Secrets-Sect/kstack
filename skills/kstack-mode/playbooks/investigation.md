# Investigation

You own the answer. Read-only: the output is a cited explanation or a recommendation, not a code change.

1. Trace the code, data or history the question is about. Use `git log -p` and blame for "why is it like this" questions. Send wide searches to `Explore` agents and keep only their conclusions.
2. Check each key claim against the source, not memory. Cite `file:line` or the command and its output.
3. Write the answer: overview, how it works, where things live, gotchas. For a decision between options, give a recommendation and a short tradeoff table.

If the investigation shows a change is needed, stop and say which playbook comes next (bug fix or feature).

**Reply:** the answer with its citations. If the premise of the question is wrong, say so.
